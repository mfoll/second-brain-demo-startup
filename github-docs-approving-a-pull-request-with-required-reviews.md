# Approving a pull request with required reviews

GitHub Docs page on how reviewers approve when required reviews apply.

## Summary

Reviewers approve from the pull request's changed files view by submitting a review with "Approve". Authors cannot approve their own pull requests, and a person who assigned GitHub Copilot to the related issue cannot approve the resulting pull request. Approvals from users with write or admin access count toward merge requirements. With stale review dismissal enabled, a code-modifying push dismisses the approval.

## Why It Matters

Two uses. It confirms the self-approval rule our policy relies on. And it is why rule 4 of the [[ai-coding-tools-policy-draft]] exists: GitHub already treats whoever started an agent as too close to approve its work, and we want the same principle for any agent, not only one vendor's.
